Where G lands across the workbench

G was designed inside one chat. ThinkRail already has the same three facts at the chat level on the wire — SessionState.execution, needsInput (question or dialog) and completionUnread — with workspace and project rollups in the store, but it renders them in exactly one place: the Projects-rail rows. These frames show the whole shell with one status vocabulary applied everywhere the facts already exist, plus the two places G itself reaches beyond the popover: the composer tray and a workspace-scoped inspector.

Everything is live: hover rows, click the history button, the trigger, dock rows, the scope pill; switch theme and the active chat's scenario in the sidebar. Marks are word + glyph + colour everywhere; colour alone is never the signal.

Chat tabs

  • Working = the chat glyph breathes (RunningIcon, as the rail does today).
  • Needs you = amber dot after the title; unread result = static green dot. Tooltip carries the word.
  • Source: selectSessionState, rendered through renderTabAdornment in WorkspaceWorkbench — today that hook only paints review flags.

Rail rows

  • Keeps today's breathing identity glyph; adds right-aligned counts working · needs you · unread from the existing rollup selectors.
  • Second line names the blocker (“waiting: question in …”) — SessionInputState.kind already distinguishes question vs dialog.
  • Proposed: a “jump to next chat that needs you” action (⌥⇧N) in the rail header; Conductor and Claude Desktop both ship one.

Composer tray

  • Merges QueueStrip and G's dock into one tray above the composer — two strips never stack.
  • Queue rows are yours (edit / remove, “next step” vs “after turn”); live rows are the agent's (Inspect / Stop). Same grammar, different glyphs.
  • Review badge turns amber: it is a needs-you signal, so it should wear the needs-you colour.

≡ One status vocabulary precondition for everything else

Today AttentionDot is green and means “needs input or unread result”; G uses amber for needs-you. The proposal keeps both existing components and changes one thing: needs-input moves to the warning colour, so blocked and done, unread stop sharing a mark. Applied to rail rows, chat tabs, the trigger, the tray and the inspector.

2 Closed chats keep running history menuno wire change

Closing a chat tab keeps its runtime and host session alive (closeChatToHistory) — so a closed chat's dev server and subagents keep going, and today nothing but the workspace rollup hints at it. The history menu gets the same marks: Theme audit is still working with a storybook server running, Pierre diff review finished unread. The history button itself carries a dot when anything closed is live.

Try: hover a closed row → Inspect its resources / Reopen / DeleteInspect on “Theme audit” → the inspector opens in workspace scope at its storybook serverEsc closes the menu

What changes

  • WorkspaceChatHistory rows gain glyph + mark + a one-line status (“still working · 1 resource running”, “needs you · question”, “finished · result unread”).
  • The button shows a dot while any closed chat is working or blocked — otherwise the only trace is the rail rollup.

Why it matters

  • “I closed the tab; is the dev server still running?” has no answer in the UI today. Several competitor bug threads are exactly this confusion (Cursor's zombie rows, Codex's archived-yet-spinning threads).

Contracts

  • Chat status: sessionStateByWorkspace already covers closed sessions.
  • “1 resource running” on a closed chat needs that chat's resources — the workspace-level read from frame 3.

3 Workspace-scoped inspector G's inspector + direction C's scope switchneeds one wire read

The same inspector, with the scope pill switched to Workspace: this chat's rows first, then other open chats' background work, then closed chats' — grouped by chat, same row grammar, same detail pane. It answers “what is running anywhere in this worktree?” without a new pane, and it is where the history menu's Inspect lands.

Try: scope pill → back to “This chat”click rows across chats, ↑ ↓ walks the whole listStop on a closed chat's server → it stops; closing the chat never did

Scope rules

  • Default scope is This chat — the inspector stays chat-first; Workspace is one click and remembered per workspace.
  • Groups: this chat · open chats · closed chats (with “closed N ago”). Needs-you rows still sort first inside each group.
  • Stop-all stays scoped to the current chat's subagents; no cross-chat mass stop.

Contracts

  • One new read: workspace.resources({ workspaceId }) (or session.resources accepting a list), plus session.resourcesChanged fan-out per workspace. Output/transcript reads stay per selected row.
  • Everything else — row model, detail polling, authority rules — is unchanged from G.

Not in scope

  • User-owned terminals stay out (spec rule); project- or app-wide scope is a fleet view and belongs to the rail, not the inspector.
