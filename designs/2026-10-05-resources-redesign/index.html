How should background work look in a ThinkRail chat?

“Resources” are the things an agent starts that outlive a tool call: background commands and subagents. Today they live in a header popover with three-line rows and lowercase status words. These mockups explore six placements for the same data, each rendered with the real ThinkRail palette, type scale and spacing — switch theme and scenario in the sidebar; everything below is live (hover rows for actions, click triggers, stop things).

Each direction lists what it borrows from competitors, its trade-offs, and whether it fits the current contracts (SessionResources, backgroundCommand.output, subagent.getTranscript) or needs a wire change. Fields marked proposed — live activity, needs-input, model/usage, nesting — do not exist on the wire yet.

Where this landed: after review, the header trigger and row grammar of A, the composer dock of B and the inspector of F were combined into G, shown first. A–F stay below as the explored alternatives and as the component sources. A second page, G across the workbench, applies the same vocabulary to chat tabs, rail rows, the composer tray, the closed-chat menu and a workspace-scoped inspector.

0 Baseline — what ships today header popover

Captured from the running app with a populated snapshot (dark theme). Functional and honest about authority, but every row is a three-line stack with a lowercase status word, no elapsed time, no activity, and ghost text buttons that read as content.

Keep

  • Authority discipline — unknown count renders as “—”, stale snapshots disable controls, Stop means “requested”. Several competitors' worst bugs are exactly here (Cursor's stuck “Starting up”, Codex's eternal spinners).
  • Finished stays reachable (contracts retain 20) and never stops work on close.
  • Header placement — zero footprint when idle.

Fix

  • Status is a lowercase word with no glyph/colour; “running” and “queued” look identical at a glance.
  • No time: no elapsed, no duration, no “since when”.
  • Raw command / full task as a headline; actions as a third line of text buttons → 90 px per row.
  • “Stop all subagents” competes with the section title; no confirmation affordance visible.
  • Logs open a modal that covers the chat; no way to glance at a tail.

G Combined — trigger · dock · inspector recommendedA + B + Ffits current contracts

Three surfaces, one roster, one row grammar. The header trigger (A) is the always-present control: count, breathing dot while anything is live, amber marker when a child needs you. The composer dock (B) is the ambient view — live rows only, Stop on hover, Claude Code's footer panel in spirit. The inspector (F) is the detail view: it slides over the message list (the composer stays usable) with the full roster on the left and the selected item's log tail or transcript on the right. Every way in — trigger, dock row, the “N still running” chip, Inspect on an Agent or background-command card — opens the same inspector at that item; while it is open the dock yields so the live list never renders twice.

How the pieces fit

Trigger
Only always-present control. Count = authoritative live rows; dot breathes while live; amber marker when a child needs you; — while the snapshot is unauthoritative. Toggles the inspector.
Dock
Live rows + the most recent failure until dismissed. Row = glyph·dot · name · activity · state · elapsed; hover → Inspect / Stop; click → inspector at that row. Collapses past five rows but pins needs-you rows; disappears when idle; hidden while the inspector is open.
Chat
No inline roster. The turn-divider chip (“N still running”) and tool cards are receipts that deep-link into the inspector. Cards keep their own expand/collapse.
Inspector
Roster (Needs you / Active / Finished) + detail in one surface: metadata, live log tail or read-only transcript preview, Stop, open full transcript. Replaces the popover, the log dialog and the transcript peek. ↑↓ switch, Esc closes, focus returns to the opener.

Rules it keeps

  • One live roster at a time — dock or inspector list (T3's lesson).
  • Same row grammar everywhere; one in-flight colour; failure loud, success quiet, stopped neutral (Kiro).
  • Authority discipline unchanged — unknown count is —, stale snapshot disables controls, Stop means “requested”.
  • No composer jitter — the dock reserves its rows and animates once; the inspector never pushes layout (Codex #10962).
  • The inspector covers most of the transcript while open — that is the trade for not stacking a popover on a dialog. Phones get a full-height two-step sheet (list → detail).

Contracts

  • Dock and inspector list render today's SessionResources; the detail polls backgroundCommand.output / subagent.getTranscript for the selected row only — the same rule as today's open detail.
  • Proposed: subagent live activity + needsInput; model/usage; parentId for nesting. The design degrades gracefully without them (activity falls back to the task).
  • Spec impact: resources/SPEC.md moves from “header popover” to “trigger + dock + inspector”; the chat spec's “no new shell pane” holds — everything lives inside the chat column.

A Roster popover trigger + row grammar → reused in Gfits current contracts

Same placement, new content: one unified list sorted by urgency (Needs you → Working → Stopping → Queued), each row a single sentence glyph · name · activity · elapsed, actions on hover/focus, Finished folded with a count. The trigger breathes while anything is live and carries an amber marker when a child needs you.

Try: hover a row → Logs/Transcript + Stopclick Stop on “scout” → Stopped (neutral)Stop all → confirmation names the countFinished ▸ toggleScenario “Stale” → controls disabled, trigger shows —

Borrowed from

  • Claude Code /tasks: running sorted first, one dialog for shells and agents, Enter = output + Stop.
  • T3 Code: one in-flight colour (“Working”), only settled states differ; failures loud, success quiet.
  • Kiro Crew: stopped is neutral, not a failure; Stop-all behind a confirmation with the count.
  • OpenCode: finished list kept short and folded.

Trade-offs

  • Zero footprint when idle; keeps the existing a11y contract (name = state word + glyph + colour).
  • Row height 32 px vs ~90 px today → 2.5× more rows per popover.
  • Still blind while closed; the trigger's dot/marker is the only live signal.
  • Unified list drops the Commands/Subagents section split; the glyph has to carry the kind. (Alternative: keep two sections, same rows.)

Contracts

  • Everything shown exists today: name/command, task/role, status, startedAt/finishedAt/exitCode, errorMessage/abortReason.
  • Proposed: subagent live activity line and needsInput; model/usage per child.

B Composer dock dock → reused in Gfits current contracts

A borderless strip docked above the composer lists only live work (plus a recently-failed row until dismissed). It auto-collapses to one summary line past four rows and vanishes when idle. The header trigger still opens the full roster with Finished — the dock is the live view, the popover is the history.

Try: hover a dock row → Stop“hide” collapses to the summary line× dismisses the failed rowScenario “Fan-out” → auto-collapsed summaryScenario “Idle” → only a dismissible failed row remains; × it and the dock is gone

Borrowed from

  • Claude Code's subagent panel below the prompt (↑↓ · Enter · x · Esc) and Qwen Code's LiveAgentPanel: “status · name · activity · elapsed, borderless so it sits lightly above the composer”.
  • Cursor “N Working” panel: count header, Stop All, children indented.
  • Codex #10962: one canonical summary string, never a row that jitters the composer.
  • OpenCode: active list collapses past one row and remembers it.

Trade-offs

  • You see work the moment it starts, where you type; stop is one hover away.
  • Keyboard-reachable from the composer (↑ into the dock).
  • Costs 26–130 px of vertical space in a column that already hosts the plan strip; must animate once and reserve height.
  • Two surfaces (dock + popover) risk the “roster rendered twice” problem T3 hit — rule: live rows only ever appear in the dock.

Contracts

  • No new reads; the dock renders the same snapshot.

C Activity side tool workbench paneneeds new wire reads

Resources become a singleton side tool next to Specs/Files (movable like every other tool). Room for a second line per row (task · model · usage), a two-line output tail under live commands (Codex /ps), and a scope switch from “This chat” to “Workspace” that groups other chats' work. The chat header keeps a small “Activity · N” jump button.

Try: scope pill → Workspace groups another chat's workhover rows → actionsFinished ▸

Borrowed from

  • Claude Code Desktop “tasks pane” (subagents + shells + workflows, click → output in the subagent pane).
  • T3 Code Agents panel; Kiro Crew Activity panel (task · elapsed · status · Stop/Stop all/Retry).
  • Codex /ps: command plus up to three recent non-empty output lines.
  • Antigravity /agents: subagents grouped by triggering prompt; K kills row + children.

Trade-offs

  • The only direction with room for tails, usage and nesting without a modal.
  • Natural home for a workspace-wide view (“what is running anywhere here?”).
  • Another tool tab that is empty most of the time; competes with Changes/Review for side real estate.
  • Breaks the current spec's “no new shell pane” decision and the chat-scoped contract.

Contracts

  • Tail preview needs backgroundCommand.output polling outside an open detail (today limited to the open dialog) or a tail field on session.resourcesChanged.
  • Workspace scope needs a workspace-level resources read.

D Inline receipts the transcript is the roster

No separate list while reading: a spawn batch gets one anchored row at its spawn point (“Kicked off N subagents · 1 working · Σ tokens — Open resources”) with the live children beneath it; a background command becomes a card with a live tail. A floating “N working” pill keeps the count visible when those rows scroll away; the popover holds Finished.

Try: hover inline rows → Stopfloating pill / “Open resources” → history popover

Borrowed from

  • T3 Code's spawn CTA row (exempt from turn folding, frozen to past tense on settle).
  • Amp: subagents as inline rows with outcome stats; Zed: Stop on the terminal tool card.
  • ThinkRail's own AgentCard / completion-card convention.

Trade-offs

  • Context at the point of delegation; receipts and live state in one place.
  • Scrolls away — hence the floating pill. Virtualised transcript rows re-render under live timers.
  • Duplicates the existing Agent/background_command tool cards unless those are replaced; the roster must never render twice.
  • Commands started in earlier turns are far up the transcript.

Contracts

  • Spawn rows derive from existing tool calls; live tails need the same output read as C.

E Pill bar switch into a child in place

Under the chat header, one pill per live resource next to a main pill. Clicking a pill swaps the chat body for that child's log or transcript in place (Stop + Back to chat); the bar shows at most five and folds the rest. Finished lives behind a trailing pill.

Try: click “vite dev server” or “scout” pills“main” returns to the chatScenario “Fan-out” → +N more

Borrowed from

  • Warp's orchestration pill bar (parent left, one pill per child with live badge, click to swap the pane).
  • Codex app's child threads nested under the parent.

Trade-offs

  • Fast glance + fast drill-in; no modal for logs.
  • Breaks down past ~5 items (Fan-out scenario); pills truncate names.
  • Implies children are peers of the conversation; subagent transcripts here are read-only, which the UI must say.
  • Permanent 36 px row even when idle unless it hides itself.

Contracts

  • Existing output/transcript reads, but polled for the selected pill while open.

F Inspector sheet inspector → reused in Gfits current contracts

The trigger opens a sheet inside the chat column instead of a popover: the roster on the left (Needs you / Active / Finished), the selected item's detail on the right — metadata, live log tail or transcript preview, Stop. Logs and transcripts stop being separate dialogs; ↑↓ moves between items, Esc closes.

Try: click rows on the leftStop on the detail header× or Esc closes

Borrowed from

  • Claude Code agent view: list + Space peek pane; Claude Desktop tasks pane → subagent pane.
  • Antigravity Subagent Detail View; Gemini CLI Ctrl+B toggling the current shell's output.

Trade-offs

  • One surface replaces popover + log dialog + (for a peek) the transcript dialog; detail polling reuses the existing single-flight loop.
  • Keyboard model is simple and matches the existing focus-return rules.
  • Covers most of the chat while open; needs a min width (~520 px) so phones fall back to a full-screen sheet.
  • Heavier than a glance; pair with the trigger dot (or B's dock) for ambient awareness.

Contracts

  • Uses backgroundCommand.output / subagent.getTranscript for the selected row only — same rule as today's open detail.

Header trigger states shared by A · B · D · F

The trigger is the only ambient signal in the popover-based directions, so it has to carry three facts honestly: how many things are live, whether any needs you, and whether the number can be trusted.

Row vocabulary one grammar for every direction

A resource row reads as a sentence. The kind glyph carries a status dot; the state is always glyph + colour + word; time is right-aligned and tabular; actions appear on hover/focus and replace the state text so the row never grows.
