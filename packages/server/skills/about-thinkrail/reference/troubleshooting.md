# Troubleshooting ThinkRail

Use this table to diagnose common problems. When a dedicated skill owns the fix, switch to it
rather than improvising.

| Symptom | Likely cause | What to check / do |
| --- | --- | --- |
| **No models available / "Connect a provider"** | No provider signed in, or provider catalog is still empty / token expired | Open **Settings › Providers** to sign in (OAuth or API key), connect JetBrains AI (`central`), or add a custom server. Check **Settings › Models** for the default model. |
| **JetBrains AI won't connect / shows outdated or stopped** | `central` CLI missing, outdated, signed out, or its local proxy stopped | Open **Settings › Providers** and follow the JetBrains AI card (install/update `central`, sign in, or start proxy). You can also run `which central && central --version` to verify it is on `PATH`. |
| **PR buttons or PR review say GitHub isn't connected** | GitHub CLI (`gh`) is missing or not authenticated | Run `gh --version` and `gh auth status`. Install `gh` and run `gh auth login` in a terminal, then check **Settings › Integrations**. Note: plain `git clone` / push uses your local Git/SSH credentials, not `gh`. |
| **Can't create or open a project / git errors** | `git` is missing from `PATH` (common when launched from macOS Dock with a custom shell `PATH`) | Run `git --version`. Install `git`, or add the directory containing `git` to `PATH` in **Settings › Environment** and restart ThinkRail. |
| **A skill from Claude / Codex / Copilot / Gemini isn't showing up** | "Skills from other agents" is off, or the skill lives in an untrusted repo | Turn on **Skills from other agents** in **Settings › Extensions & skills** (or per project in the chat's Skills dialog). For repo skills (`.pi/skills`, `.claude/skills`, `.github/skills`, `.gemini/skills`), grant project trust first. |
| **A personal skill exists but isn't listed in the system prompt** | Large skill catalogs are truncated to a prompt budget | Normal behavior — the agent discovers unlisted skills via `skill_search`, or you can invoke any admitted skill explicitly with `/skill:<name>`. |
| **MCP server fails, needs sign-in, or its tool is missing / blocked** | Config error, OAuth needed, repo server unapproved, or tool is `deferred` | Follow the `managing-mcp-servers` skill. Remember: never run `pi mcp …`; inspect `~/.pi/agent/mcp.json` or `.pi/mcp.json` and use **Settings › MCP servers** for OAuth and approvals. |
| **Custom ThinkRail extension didn't load** | Build error, wrong API version, or invalid `extensions.json` | Follow the `making-thinkrail-extensions` skill (check `$THINKRAIL_DATA_DIR/extensions/status.json`). |
| **External editor missing from "Open in" menu** | Editor CLI (`code`, `idea`, `webstorm`, `pycharm`, `goland`, `rider`, `clion`, `phpstorm`, `rubymine`, `emacs`, `vim`) is not on the host `PATH` | Install the editor's shell command (e.g. VS Code "Shell Command: Install `code` command in PATH" or JetBrains Toolbox shell scripts) or add its bin folder in **Settings › Environment** and restart. |
| **Voice input fails to download or start** | Network/firewall or corporate MDM blocked the Nemotron speech engine (`nemo-speech`) | Check **Settings › Voice input** to retry the download, or verify whether an organization policy blocks unsigned binaries. |
| **Command-line tools work in terminal but not in desktop app** | Desktop app launched from Dock/launcher missed shell profile `PATH` or env vars | Set the needed environment variables in **Settings › Environment** and restart ThinkRail. |
| **Drag-and-drop file attachment doesn't work on Linux** | Platform limitation in the Linux desktop webview | Use the paperclip button or paste instead. |
| **`⌘?` opens Safari/Chrome Help instead of shortcuts** | macOS browser reserves `⌘?` for its Help menu | Click the keyboard icon at the bottom of the left rail, or open **Keyboard shortcuts** from `⌘K`. |
| **Edited `~/.thinkrail/config.json` by hand and changes vanished** | The running host caches `config.json` in memory and overwrites it on the next Settings change | Always change ThinkRail settings in the **Settings** UI (or edit `config.json` only while ThinkRail is fully stopped). Watched `pi` files (`mcp.json`, `settings.json`, `models.json`) can be edited live. |
| **How to check installed version** | Need version for a bug report or feature check | CLI: run `thinkrail --version`. Desktop: check **Settings › Updates** (or the app's About menu). |
