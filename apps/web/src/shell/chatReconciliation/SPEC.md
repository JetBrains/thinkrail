## Responsibility

Converge host-owned chat/session existence and transcripts with this frontend surface's workspace-local placements, render cache, and history—without turning cache state into placement authority.

## Boundary

- **Owns:** generation-qualified hydration for locally placed chats; authoritative session-list reconciliation with bounded passive auto-open; exact-chat route-target validation and first-priority local placement/focus; failed catalog/transcript reporting and retryable history fallback; missing/tombstoned session pruning; chat-location/deep-link orchestration; and stale-read/local-placement rechecks before installation.
- **Public surface (`index.ts`):** mounted tombstone, catalog/cache, and chat-location reconciliation hooks plus locally placed-chat hydration/current-destination operations required by intent handling and retry UI.
- **External deps:** contracts chat/session types; chat transcript hydration; store session/cache/navigation APIs; transport session reads; shell-neutral `lib`; React.
- **Forbidden:** host session lifetime, terminal reconciliation, frame geometry/topology, generic placement policy, feature-panel rendering, server/shared/pi imports, current-layout transport, or selecting a tab merely because domain hydration arrived.

Every asynchronous path verifies connection generation, workspace/session tombstones, current request identity, and surviving semantic local placement before installing state. An exact-chat route target owns its session hydration while unresolved, preventing duplicate reads. Only successful authoritative absence consumes an unresolved target; catalog/transcript failure retains it for reconnect. Once its local placement, workspace attention, and runtime converge, the target clears and URL sync resumes.

Locally persisted chat references hydrate on workspace activation. On the authoritative session-list read, **only when no exact-chat route target is being handled in that same pass**, up to `AUTO_OPEN_CHAT_LIMIT` (4) unplaced sessions that are still live or have open todos are opened passively, newest first; if the workspace opens with nothing placed and nothing qualifies, the single most-recent session opens as a fallback so a workspace never lands empty while chat history exists. Classification and the fallback draw from every unplaced session on the read, regardless of whether its runtime is already known locally (e.g. one `closeChatToHistory` just unplaced, which keeps the runtime alive precisely so this can happen) — a known session reopens straight from cache (existing `tabsByWorkspace` entry, or a synthesized one titled from `closedChatsByWorkspace`/the summary) instead of refetching; only a session with no local runtime yet goes through the fetch-and-hydrate path. A pass that is resolving a route target skips passive auto-open entirely instead of merely excluding the target's own session — otherwise an unrelated live chat opened alongside it could win the group's selection out from under the link the surface was asked to land on. Passive auto-open is attempted **at most once per (workspaceId, connectionGeneration)**, latched in a module-level set keyed by workspace id and cleared whenever the connection generation advances — not a per-mount ref, since `WorkspaceWorkbench` remounts on every workspace switch (`key={activeWorkspaceId}`) and a ref would forget the attempt the moment the surface leaves and returns to a workspace. Two things this latch defeats: the session-list effect re-fires on every `commit` identity change (its caller recreates `commit` whenever the document changes, e.g. right after this same effect places a tab), so without it a route target that resolves and clears between two of those re-fires would let a later same-mount pass — now target-free — passively open an unrelated live session out from under it; and switching away from a workspace and back must not look like a fresh arrival, or a chat another frontend started while this one was elsewhere would open locally instead of landing in history like any other post-attempt arrival. Everything else — including a live/unfinished session once the limit is spent, or one that arrived after the attempt was already spent — enters history only. A failed placed transcript read is reported and leaves the session retryable in history; a failed catalog is reported instead of presenting unexplained emptiness. Cancelled, disconnected, or removed-workspace passes stay silent. Every accepted local transition is synchronous, so chat-location work needs no host-layout-write barrier; request-time navigation stamps alone prevent a stale jump from undoing a newer close or selection.
